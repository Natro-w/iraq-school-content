# Iraq School Content — Redesign Report (2026-08-19)

Scope: full audit + redesign of `Natro-w/iraq-school-content` (books + ملازم for the
Iraq School app), with tooling, migration, benchmarks, and CI. Companion doc:
`docs/architecture.md` (assessment + design rationale, P1–P10 problem list).

## 1. Problems found (before)

1. **P1 — production-breaking catalog**: `catalog/books.json` (served by the live
   manifest to every device) had 69/143 entries with `authors` as a **string**.
   The app parser `BookInfo.fromJson` (`books_catalog.dart:192`) casts
   `(json['authors'] as List?)` → `_TypeError: type 'String' is not a subtype of
   type 'List<dynamic>?'`. Verified by running the app's real parser against the
   file. Effect: new installs got no catalog; existing installs silently kept a
   stale cached copy. The root `books.json` (167 KB, repaired by the audit PR)
   and `catalog/books.json` (405 KB, generated once in `9a40e50` and never
   regenerated) had **diverged** — 61 books differed.
2. **Cross-stage duplication**: books/notes in the preparatory stage were placed
   under primary/intermediate grade ids too (shared `grade-1..3` ids across
   stages) — ~150 duplicate catalog entries.
3. **Inconsistent grade-id vocabularies**: books (`grade-1..6`) vs notes
   (`grade-primary-0..2`, …) for the same curriculum levels.
4. **sha256 contract mismatch**: generated sha256 covered bytes without the
   trailing newline, but files ship with one — the app's byte-verified download
   would have rejected every artifact.
5. **Non-atomic regeneration**: no build/state tooling, no drift check, no CI.
6. **Thumbnails orphaned**: 489 thumbnails (14.5 MB) lived only on the `master`
   branch (commit `488a0e1`, never merged into `main`).
7. **6 relative `pdf_url`s** (`/uploaded/2025-11/…`) — resolved to
   `https://h1.iraqiteacher.com/…` (verified GET 206 `%PDF-1.4`; HEAD 403 is
   expected server behavior, GET works).
8. **No attribution/legal/removal metadata** per item; stale README (documented
   a structure that didn't exist).

## 2. Architecture chosen

Hybrid: **human-edited source** (`content/`) → **machine-generated artifacts**
(`catalog/`), with committed build state.

```
content/taxonomy.json           canonical stages/branches/grades/subjects
content/books/<id>/manifest.json   135 book manifests (strict schema)
content/notes/<id>/manifest.json   574 note manifests
catalog/manifest.json           versioned file list (app fetches first)
catalog/books.json              76,319 B — app contract BookCatalog.fromJson
catalog/notes.json              195,092 B — same tree shape
catalog/search_index.json       Arabic-normalized search index (repo-only)
thumbnails/<md5(pdf_url)>.jpg   489 restored (app-compatible naming)
tools/                          Python stdlib-only: ingest, build, validate, check_links
legacy/                         original books.json/notes.json/subjects.json + migration report
docs/, .github/workflows/content-ci.yml
```

**Format decision — JSON kept for artifacts.** The shipped app contract
(`minimumAppVersion=1`) is fixed: manifest schema, `version`/`updated_at`/`stages`
top-level, per-file names `books.json`/`notes.json`, sha256 byte verification,
atomic staging writes. SQLite/JSONL would require an app rewrite and lose the
~8 KB gzip delta sync. The **source of truth is now many small JSON manifests**
(human-reviewable diffs, per-item PRs) — validation ergonomics over CSV/JSONL.

## 3. Workflows

**Ingest (one-time, done):** `python tools/ingest.py` read `legacy/books.json` +
`legacy/notes.json`, deduped 8 duplicate ids (143 → 135 books), absolutized the 6
relative URLs, remapped notes grade ids to the canonical taxonomy (derived from
titles, e.g. "للصف الرابع الابتدائي"), wrote manifests + `legacy/migration_report.json`.
0 skipped, 0 unknown subjects.

**Indexing (ongoing):** `python tools/build.py` — deterministic (sorted keys,
compact JSON, stable taxonomy order) and **incremental**: per-file sha256 diff vs
committed `.catalog_state.json` bumps only the affected file's `version`;
`catalogVersion` bumps only when something changed. `search_keys` (Arabic
normalization: أإآ→ا, ة→ه, ى→ي, strip diacritics/tatweel, collapse whitespace) live
only in `search_index.json`, keeping the wire artifacts minimal. `--check` fails
if committed artifacts are stale (CI gate). No build → no manifest changes → no
app churn.

## 4. Performance (measured)

| artifact | before raw | after raw | before gzip | after gzip | decode before→after |
|---|---|---|---|---|---|
| manifest.json | 505 B | 372 B | 290 B | 265 B | — |
| books.json | 405,066 B | 76,319 B | 14,317 B | 7,428 B | 2.3 → 0.83 ms |
| notes.json | 753,493 B | 195,092 B | 34,804 B | 25,867 B | 4.9 → 1.80 ms |

Wire: books **−48%**, notes **−26%** (gzip); decode ~2.8× faster. Network fetch
(raw.githubusercontent.com, measured from this region) is latency-bound
(2.3–5.0 s round trip) — the size cut matters most on slow 2G/3G links.

**Scaling projection** (per-entry cost: book ≈ 565 B, note ≈ 340 B raw; gzip ≈
10% of raw):

| entries | books.json raw/gzip | notes.json raw/gzip |
|---|---|---|
| 10k | 5.7 MB / 0.55 MB | 3.4 MB / 0.44 MB |
| 50k | 28 MB / 2.8 MB | 17 MB / 2.2 MB |
| 100k | 56 MB / 5.6 MB | 34 MB / 4.4 MB |

Above ~50k, the documented **additive shard path** applies: split artifacts into
per-stage shard files (`files[].dependsOn`), gated by a future
`minimumAppVersion=2` — additive, non-breaking. Thumbnails scale as content-
addressed md5 files (already deduped); ~30 KB avg each.

## 5. GitHub strategy

- `main` = production catalog. `master` = retired (thumbnails merged onto main).
- CI (`.github/workflows/content-ci.yml`): on push to main / PR — `validate.py
  --strict` + `build.py --check` (drift gate). Contributors edit `content/`, run
  `build.py`, commit artifacts + state; CI enforces reproducibility.
- `check_links.py` is a manual maintenance tool (external PDF health, network
  heavy) — intentionally not in CI.
- No LFS: repo ≈ 14.5 MB thumbnails + ~1 MB content, well within limits.

## 6. Security

- External files treated as untrusted: `check_links.py` verifies `%PDF` magic
  (Range GET, 8-byte sniff) before trusting content-type.
- `validate.py` enforces absolute-https `pdf_url` (no SSRF-able schemes) and the
  app parser contract (P1 regression guard, incl. `authors` list check).
- Artifacts are sha256-verified by the app on download; manifest/state version
  equality enforced by validation.
- No secrets in repo; CI is read-only (`permissions: contents: read`).

## 7. Migration done (non-destructive)

1. `legacy/` holds original `books.json`/`notes.json`/`subjects.json` +
   `migration_report.json` (renames, 100% preserved in git history).
2. `content/` manifests ingested from legacy data (dates/`migrated_from` recorded).
3. `catalog/` regenerated: catalogVersion 8, books v6, notes v5 — parse-verified
   with the app's real parser (135 books OK).
4. Thumbnails restored from `master` (`git checkout remotes/origin/master --
   thumbnails/`); 105/135 current books match; 6 books (the relative-URL set) have
   no remote thumbnail anywhere — the app falls back to local generation
   (documented, acceptable). The remaining 384 files are kept for older installed
   caches that reference legacy md5 names.
5. README rewritten; `docs/architecture.md` + this report committed.

## 8. Exact commands

```
python tools/ingest.py                 # one-time migration (done)
python tools/build.py                  # regenerate artifacts
python tools/validate.py --strict      # content + contract validation
python tools/build.py --check          # drift gate (CI)
python tools/check_links.py            # external PDF health report (manual)
```

## 9. Known risks / follow-ups

- 17 duplicate `pdf_url`s across items (e.g. literary-branch books share files
  with regular-branch entries; prep-grade-6-arabic-120/121 vs 128/129, islamic-130)
  — pre-existing content facts, surfaced as INFO in validation; de-duplicating
  entries is a content decision for the owner.
- 6 books without remote thumbnails (fallback path active).
- `updated_at` on all migrated manifests = 2026-08-19 (migration date); future
  content edits will carry real dates.
- `pdf_sha256`/`checksum` fields exist in schema but are unpopulated (network
  fetch optional; future).
- Free search API for the app (search_index.json) is ready but not yet wired into
  the manifest (needs `minimumAppVersion=2` gating) — intentional.
- Old app builds' cached catalogs still reference old thumbnails/URLs — kept
  working by retaining legacy thumbnails.
